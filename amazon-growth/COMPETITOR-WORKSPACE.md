# 双界面共享 MCP 与证据方案

状态：第一阶段已落地 · 2026-09-12

## 最终边界

- `http://localhost:8787/`：西柚运营调用台，保留 31 条专项场景。
- `http://localhost:8787/asinscope/`：完整竞品分析，页头与调用台互相切换。`3210` 仍可作备用入口，路径相同。
- `http://localhost:8787/watchlist/`：监控清单，从调用台左栏拆出。清单、周期报告和任务历史只留在本页。
- 三个工具共用同一套 MCP 连接池和标准化证据缓存，不复制 Token，不共享页面状态。

ASINSCOPE 用户输入目标 ASIN，可选 1–5 个对比 ASIN，一次看到商品定位、销量与排名、流量结构、关键词、爆发归因、价格动作、变体、VOC 和可复制策略。分析章节、指标阈值、驱动权重与输出模板可以在 3210 工具内独立配置。

## 界面独立原则

- 8787 页头可切到 `/asinscope/`，不嵌入 iframe，不把竞品分析塞进 31 条场景。
- 竞品页不读取调用台的表单、当前场景、主题、弹窗和报告展示状态。
- 两边分别保存自己的项目列表和任务历史，避免一个工具刷新或清空后影响另一个。
- 允许用户从 8787 导出一份“证据引用”，再由 3210 导入；传递的是证据键和公开业务参数，不包含 Token。
- 两个工具同时请求同一接口时，由共享网关做并发合并和缓存命中。

### 固定头部

- 目标 ASIN、站点、日期窗口、对比 ASIN。
- 显示缓存命中、预计新增调用次数、分数据源调用数。
- 用户点击“开始分析”前就能知道额度成本。
- “仅用已有数据”默认可用；不会因为打开页面自动调用 MCP。

### 核心结论条

首屏只回答六件事：

- 它卖什么以及目标用户。
- 月销量量级与趋势。
- 处于起量、增长、成熟还是衰退阶段。
- 自然流量与广告依赖。
- 当前最大增长驱动。
- 最大风险或不可复制因素。

每项必须带证据等级：高 / 中 / 低 / 数据不足。

## 共享服务方案

建议增加本机共享服务 `mcp-evidence-gateway`，由它统一管理：

1. 西柚与卖家精灵连接池。
2. Token 加密存储。
3. MCP 调用、限流切换、超时和错误归类。
4. 标准化证据缓存、TTL 和并发去重。
5. 调用审计与额度计数。

两个前端只向共享服务提交 `provider + tool + arguments`。共享服务选择连接并返回数据。这样 Token 不需要分别写进 8787 和 3210 的 `.env`。

```text
8787 西柚运营 UI ─┐
                   ├─ mcp-evidence-gateway ─ 西柚 MCP
3210 竞品分析 UI ─┘                       └ 卖家精灵 MCP

界面状态：各自独立
连接密钥：网关统一管理
接口证据：按标准键共享
分析报告：各自独立生成和保存
```

## 数据共享方案

### 统一证据仓库

共享证据不能只存在某一个页面的 IndexedDB，因为不同端口的浏览器存储按 Origin 隔离。证据应由共享网关保存；8787 继续保留 `xiyou-console-cache-v1` 作为本地运行恢复，3210 保留自己的任务库。

建议对象仓库：

```js
sharedEvidence: {
  key,                 // provider|site|entity|tool|argsHash
  provider,            // xiyou | sellersprite
  site,
  entityType,          // asin | keyword | category
  entityId,
  tool,
  canonicalArgs,
  payload,
  retrievedAt,
  expiresAt,
  schemaVersion,
  sourceRunId
}

asinScopeProjects: {
  id,
  name,
  targetAsin,
  comparisonAsins,
  site,
  dateFrom,
  dateTo,
  createdAt,
  updatedAt
}

asinScopeReports: {
  key,                 // projectId|reportVersion
  projectId,
  evidenceKeys,
  sections,
  generatedAt,
  reportVersion
}
```

### 缓存键

同一请求只有在以下字段完全一致时才复用：

`provider + site + entity + tool + 排序后的真实请求参数`

日期窗口、关键词、relations、星级筛选不同，必须形成不同缓存键。Token、连接名称和请求头不得进入缓存。

### 推荐有效期

| 数据 | 有效期 | 说明 |
|---|---:|---|
| 商品详情、变体 | 24 小时 | 价格和变体可能变化 |
| 日流量、BSR、关键词排名 | 6 小时 | 高频运营信号 |
| 月订单、月流量 | 24 小时 | 日内重复请求价值低 |
| 类目、价格带、市场结构 | 7 天 | 大盘变化较慢 |
| 评论正文 | 14 天 | 同一批样本无需反复拉取 |
| Keepa、优惠趋势 | 24 小时 | 新增日期可按需补取 |

过期数据仍可显示，但标记“已过期”。系统不自动刷新，由用户点击“补齐缺失”或“刷新过期数据”。

### 写入规则

- 8787 的场景运行成功后，由网关缓存每个 MCP 成功响应。
- 3210 运行竞品分析时优先命中相同的证据键；它生成的 MCP 响应也可反向供 8787 使用。
- 两边只共享原始/标准化证据，不共享对方生成的业务结论，避免自定义权重污染另一工具。
- 同一请求正在执行时，后来的模块共享同一个 Promise，避免并发重复调用。
- 错误和空数据不覆盖较新的成功缓存；保存错误原因和尝试时间用于诊断。
- 报告保存其 `evidenceKeys`，之后可以确认每条结论用了哪批数据。

### 旧数据迁移

8787 已有的 `good:s7`、`good:s8`、`good:s9` 等结果仍保存在原 IndexedDB。可增加一次性“发布到共享证据库”操作：

1. 校验站点、ASIN 和真实参数。
2. 将成功步骤转换为共享 evidence，并提交到本机网关。
3. 保留原始 `good:sceneId`，不删除、不改写。
4. 参数不明或旧结果站点不一致时不迁移，只显示“旧结果不可安全复用”。

## 调用模式与额度

### 快速模式

- 只用缓存；缺少首屏必要信息时最多补 5 个西柚接口。
- 目标：商品、近 30 天订单、流量、BSR、变体。
- 适合每天快速查看。

### 标准模式

- 对目标 ASIN 建立九章节报告，预计 12–18 个唯一请求。
- 所有重复步骤经过证据仓库合并。
- 默认模式，适合完整运营分析。

### 深度模式

- 增加卖家精灵详情、Keepa、优惠、评论、关联流量和预测。
- 预计在标准模式之外增加 5–9 个唯一请求。
- 只有用户主动选择才运行。

### 多竞品

- 对比 ASIN 默认只拉商品、订单、流量和 BSR 四项。
- 只有用户展开某个竞品时才补关键词、动作和 VOC。
- 最多 5 个对比 ASIN，避免一次把额度打满。

## 结论规则

- 原始数据、计算指标、推断结论用三种标签分开。
- 每条结论必须保留 `source tool + retrievedAt + sample/window`。
- 无法取得花费、利润、库存、退货率时，不输出必投、必备货或盈利结论。
- 竞品广告新增不等于广告持续运行；流量得分不等于曝光；第三方销量不是后台订单。
- 完整报告不得把“成功步骤数”或“记录条数”当业务结论。

## 验收标准

- 打开任一页面不调用 MCP。
- 同一 ASIN、同一接口和同一参数只调用一次。
- 页面能显示预计新增调用数和数据源拆分。
- 刷新后两边各自的项目和报告仍存在，彼此页面状态不串联。
- 旧场景结果可安全迁移，旧 IndexedDB 不被删除。
- 任一章节缺数据时，其余章节仍正常显示。
- 所有结论能回溯到来源接口和取数时间。
- 3210 标准模式完成后，8787 专项场景的相同请求能命中共享证据，反向同样成立。
- 浏览器前端和 API 响应中都不能看到 MCP Token。
