# 修复与回归说明

## 已修改

- 本地代理仅监听 127.0.0.1，校验 Host 与 Origin；只公开首页和已知静态资源，拒绝隐藏文件、目录穿越及越界符号链接。
- MCP 上游端点固定为服务端 MCP_ENDPOINT，禁止请求覆盖与 HTTP 重定向，避免服务端密钥被带往其他地址。
- 部署版 MCP / Claude 接口要求 PROXY_TOKEN，未配置时关闭调用；两版增加 JSON 对象校验、8 MiB 请求限制、60 秒上游超时。
- 工作流加入互斥锁，运行与分析期间阻止重复启动、切换场景和修改连接配置；每次运行保存表单快照，后续步骤与分析沿用该快照。
- 单接口复用工作流校验；增加 ASIN 格式、20 个数量上限、日期存在性和顺序校验。参数映射改为明确别名匹配，检查必填、枚举、数字及部分长度范围。
- MCP 工具错误不再计为成功；校验响应 ID，修复 SSE 尾帧、读取工具列表分页；空行数据和嵌套数据增加容错。
- 分析请求加入独立系统指令，将接口数据视为不可信数据。此项降低提示注入风险，但不代表模型安全性已被证明。

## 验证

42 项自动化测试全部通过，详细结果见 results.json，执行命令为 `npm test`。失败时退出码为 1。

测试使用真实本地 HTTP 与文件读取；前端、部署版函数在 VM 中执行；上游使用模拟 fetch，未使用真实密钥或调用付费服务。覆盖原始问题、正常请求、部署版授权与拒绝、超大请求、参数快照、日期和 ASIN 数量边界、分页读取。

另已在真实浏览器检查：页面与设置正常加载；ASIN=x 时运行按钮禁用；合法格式恢复按钮；缺少服务端端点时显示配置错误并恢复可操作状态。测试输入已清空。

原始报告中“损坏 URL 返回 socket hang up”受到测试 HTTP 连接复用干扰，不能单独作为原程序缺陷证据；现已隔离连接，验证无效编码返回 400。

## 使用方式变化

本地执行 `npm start`，访问 http://localhost:8787 。本地服务已为本次检查启动。

在启动服务前设置 MCP_ENDPOINT、MCP_API_KEY，以及分析需要的 ANTHROPIC_API_KEY。代理模式下页面 MCP 端点留空；不能再由浏览器改写服务端端点。若使用 .env，Node 20.6+ 可运行 `node --env-file=.env proxy/server.js`；普通 npm start 不自动加载该文件。

部署版还必须设置 PROXY_TOKEN，并在页面填写同一令牌；ALLOW_ORIGIN 设置为实际页面来源（协议、域名与端口，无路径）。本地默认仅接受 http://localhost:8787，不再支持 file:// 页面调用代理。

## 尚未覆盖

真实 MCP 服务的 schema 兼容性、完整 JSON Schema 高级关键字、真实 Claude 分析质量、生产压力与额度控制尚未验证。现有令牌用于单人访问控制，不是多用户账户/配额系统。原有配置保存在浏览器 localStorage 的行为仍保留，服务端密钥建议仅配置在服务端。
