# 清洗识别与源证据一致性修复

状态：本地修复及验证完成，待审阅；未合并、未发布。分支codex/cleaning-evidence-consistency，基于待发布PR118；不是线上V1.0.66.e的既有行为。

## 修复的具体问题

1. 金额门槛不一致：预判和AI疑似行识别共用现有Domain.cents规则，合法千分位及人民币/美元等符号不再被纯数字正则提前拦下。仍拒绝无效金额和无法计算的公式，不更改原价、币种或源文本。
2. 全量证据遗漏：在原始整本模型上重建逐单元格证据，保留未清洗表、说明、公式、合并范围和附件；不再以裁剪工作集作为完整清单。
3. 明确税务否定词误判：新增纯CleaningIntegrity投影，修正不包税/非包税/未包税等明确源声明；可选或矛盾声明标为待确认。未注明税务仍保留现有默认规则，未借修复改变受锁定默认值。
4. 按档与整本时序不一致：按档默认字段读取显式渠道及合并范围，转标准校验前同步投影，AI不是字段纠正的必经步骤；人工修改渠道/税务后保留manualSourceFields，晚到AI投影不覆盖。
5. 解析问题只留reports：错误价格格在证据清单中标为价格待核对；页面单独显示工作表、坐标、原值和原因，不能将“0条入库冲突”等同“0个源价格问题”。这不会擅自把错误价格变成报价。
6. 表名包含“查询”导致整表跳过：只对已通过预判且存在明确矩阵的查询表恢复逐档提取；公式查价汇总仍保留引用/参考路径，不重复当基础报价。

## 集成与保护

- 新模块：tools/logistics-rating/extensions/cleaning-integrity.js；显式输入输出，不写数据库、网络或全局业务状态。

- 人工修改优先；报价原价、坐标、日期、国家/仓库校验、Amazon范围、现行运营排除、十天保留、永久模板、冲突隔离、评分公式和已保存决定保留。
- 此次不迁移历史业务库，不自动发布报价，不重建线上查询索引。
