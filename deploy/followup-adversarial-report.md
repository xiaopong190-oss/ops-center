# 新品跟踪大屏专项测试

目标版本：v2026.11.03.2。可复现命令：`npm run test:regression`。

本地结果：整站 53 组回归全部通过；全输入专项 129 组检查、上传压力专项 10 个场景均无失败。字段与表单清单随结果文件输出。

| 范围 | 验证内容 |
|---|---|
| 当前大屏全部编辑字段 | 113 个字段：链接信息、货件明细和节点、基础交付、推广方案与阶段、评论维护、经营数据；真实页面事件触发后检查保存内容 |
| 条件表单与工具栏输入 | 43 种不同的表单/工具栏控件；新增链接、货件、清单、跟进、执行动作、评论计划、差评、退回、周期数据、JSON 导入及运营/站点筛选 |
| 边界 | 零值、可清空值、所有下拉选项、负数、数量小数、数值上限及越界、评分超过 5、经济测算百分比和交叉关系、必填空格、日期范围倒置、20,000/20,001 字符、超大导入文件 |
| 输入对抗 | 脚本标签/事件字符串、Unicode 和 emoji、非 HTTP 链接、带账号密码的 URL、原型字段及字段元数据篡改、伪造只读输入 |
| 本地草稿 | 真实页面脚本搭配模拟 IndexedDB：关闭窗口后重新打开恢复；两个账号各自草稿隔离；上传后第三个账号读取最终结果与操作人记录 |
| 多运营 | 12 个旧页面先后上传，另 4 个运营同时保存；最终 16 条记录和 16 条身份明确的操作历史全部存在，各账号草稿清空，重新读取一致 |
| 上传中断 | 首片、中间片、末片分别在写入前断网和写入后丢回执；恢复前根数据不变；先查服务器回执，只上传缺失分片 |
| 大数据 | 接近 16MiB 的合成数据通过 32 个分片上传并完整比对；超限数据发起网络请求前被拒绝 |
| 上传对抗 | 上传中切换账号被拒绝，原账号可继续；过期会话重新建立；原有套件覆盖篡改摘要、缺片、跨运营读写、只读/未登录、重复分片、损坏分片修复与旧 revision 冲突 |
| 保存及清理回归 | 保留其他运营最新字段；列表冲突保留草稿；历史清理前后完整快照深度相等；清理后仍能保存和加载 |

本次修复：增加输入范围和必填校验、URL 协议及凭据检查、字段路径与控件一致性检查；在乐观更新和草稿写入前阻止非法操作。导入文件超过 16MiB 时，在读取文件内容前阻止。

测试说明：页面交互通过 JSDOM 执行实际生成页面脚本；IndexedDB 使用 fake-indexeddb；上传及多人并发使用真实 followup API 和隔离 SQLite。断网、丢回执、切换身份等由测试注入。这里的耗时不能当作线上网速或真实磁盘性能；没有向生产库写入压力数据。原有套件另含 1,000 周期页面输入和 100,000 周期最新记录选择测试。

明细输出：`test-results/followup-all-inputs.json`（字段清单与分组结果）、`test-results/followup-upload-stress.json`（上传场景结果）。整站完整结果见 `regression-input-adversarial.log`。
