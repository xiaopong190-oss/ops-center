# 新品跟进上传确认与会议核对

版本 v2026.11.14.1。针对“本机显示已上传，另一电脑找不到”的保存/读取可观测性缺口，本次前端补齐以下行为。

## 成功条件

1. 草稿先按账号持久保存；提交前从共享 API 取得最新基线并备份。
2. 校验 POST 回执的版本为基线加一，且本次修改的记录内容完全一致。
3. 再发一次独立 GET（传输使用 no-store），核对版本不倒退；同版本时完整 data 一致；操作编号、操作人和 after 内容必须存在且匹配。
4. 后续有人保存了更新版本时，允许读到更新版本，但仍要求本次不可改写的操作记录完整存在。不能承诺之后永远没人修改相同字段。
5. 草稿清理和本机成功日志持久完成后才给“上传成功 · 云端回读已核验 V…”。任何一步失败保留草稿并记录失败；丢回执后重试用操作编号去重。

没有待上传修改时也重新读取云端，提示“没有待上传修改”，不声称已分享新内容。仍在焦点中的输入框在点击上传时先提交 change 并校验。

## 上传日志

大屏顶部“上传日志”按账号显示本机最近 300 条（持久保留最近 5000 条，可导出全部）。记录点击保存、上传开始、云端基线读取、本机备份、每次传输阶段/分片计数、提交回执、独立回读、核验成功和失败。日志不保存表单正文、M 码或 token。

过程日志存于本机 IndexedDB，断网时仍可记录；云端成功修改沿用不可改写的操作事件，日志下方列出该账号云端操作编号与时间，可在另一电脑读取。未联网的失败过程不能出现在另一电脑。新增日志库将草稿库从 v1 升级到 v2，保留原草稿；旧标签页阻塞升级时显示错误而不声称成功。日志持久化失败会阻止最终成功提示。

## 会议电脑

“会议核对云端”重新读取共享库，清空运营/站点筛选，切到只显示云端的只读视图；原本机草稿继续保留，“返回编辑”后恢复。可输入上传成功提示中的版本号，当前云端版本较低则明确核对失败。读取失败、低版本、未登录均保持可见错误，不把旧画面称为新数据。显示版本、链接数量、修改人和最后修改时间，便于逐机比对。

## 测试及限制

`deploy/test-followup-cross-device.mjs` 覆盖虚假提交回执、旧版本、读取失败、内容不一致、独立读者读回、会议视图排除本机草稿、草稿保留、无修改保存、焦点输入以及会议最低版本检查。

`deploy/test-followup-upload-journal.mjs` 验证过程与结果日志、成功发生在核验后、关闭重开仍保留、失败无成功记录、原 v1 草稿保留及日志 UI。原有大数据 32 片续传、多运营冲突、跨账号权限、清理与全输入测试继续回归。

这些测试使用隔离 SQLite 和实际页面脚本搭配模拟 IndexedDB。没有向生产库写测试数据。只读查看生产快照可确认云端现状，不能单独还原此前某台会议电脑的登录状态、筛选状态、草稿或失败网络请求。所有承诺以成功时点的持久化及回读为准，不代表外部服务永不故障或之后的修改不会改变当前值。
