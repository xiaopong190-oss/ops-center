# 新品跟进 D 盘保存（2026-11-24）

生产数据目录：`D:\systemDir\Desktop\Hubstudio\新建环境3\followup-local\data`。

- `followup.sqlite` 是当前权威数据库（WAL + synchronous FULL）；不要只复制主文件而遗漏打开中的 WAL 文件。
- `latest-backup.json` 是每次完成新版本后替换写入的最新版副本。
- `cloud-latest-verified.json`、`cloud-latest-pointer.json` 是切换前云端 V575 的校验备份。
- `connection.json` 是专用连接密钥配置；权限仅当前 Windows 用户、系统及管理员；不得发给运营或提交 Git。
- `journal` 数据表记录实际请求身份、结果、版本及请求摘要，不记录密码或请求正文。

运营继续用原 Pages 网址和原账号；无需安装数据库或拿到数据文件。原 Worker 完成 session 验证后，经 service binding 发送认证身份到独立 relay Worker；只有持有服务专用密钥的 D 盘进程可以建立 WebSocket。转发层不调用持久存储 API 保存业务快照。本机主动连接外网，不开放入站端口或共享磁盘。

`cloud/followup-disk-route.mjs` 支持迁移写栅栏及开关。当前 `FOLLOWUP_DISK_ENABLED=1`、`FOLLOWUP_DISK_MIGRATING=0`，旧浏览器也通过原 API 进入 D 盘，不存在新旧页面各写一个后端的分叉。主机离线/超时返回 503/504；浏览器保留草稿并在交叉回读通过前不报成功。不要自动回退写入旧云端，这会产生两份冲突数据。

本地沿用原 API 的版本 CAS、操作历史、权限和分片校验。每次提交完成后删除旧快照与不再引用的旧分片；完整操作历史留在最新数据中。上传暂存按原有效期保留；旧快照不会再按每次保存累积。主库与最新版副本都在同一 D 盘，不构成异地灾备。

## 运维

主机必须登录 Windows、开机联网，并保持此目录不移动/删除。锁屏可以；关机/断网不可上传。登录自动启动项 `OpsFollowupDisk`，手动启动 `followup-local/start-hidden.ps1`（隐藏运行）。如 Windows 浏览器草稿库被旧标签页阻塞，关闭其他运营中心标签页后刷新；不要清除浏览器数据。

切回云端前先冻结写入，把 D 盘最新版本校验导回云端，验证所有记录，再关闭 DISK_ENABLED；不能直接回滚 Worker 到旧云端 V575。恢复书签有平台保留期限，不是永久备份。建议另做异地/另一硬盘备份。

测试：本地 SQLite 的只读/版本冲突、>3MB Unicode分片、4运营并发、重启持久化、最新版备份与无快照累积；relay 的未认证拒绝、非法路径、只读、异源socket响应、离线/断开失败；原完整 Worker 权限及分片认证测试、最终回执恢复测试继续通过。所有破坏/压力用例均使用隔离数据库。
