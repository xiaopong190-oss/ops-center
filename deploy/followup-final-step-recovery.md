# 最后一步网络中断恢复

版本 v2026.11.16.1。现有上传在最后 POST commit 的回执丢失时立即暂停，即使服务端可能已保存；最终独立 GET 也没有针对短暂网络失败重试。

此次在提交网络失败、408/429 或 5xx 后仅做 GET 核对：版本须大于原基线，全部本次操作编号、操作人、before/after 必须匹配；找回结果后仍再次独立 GET 交叉确认，才允许显示成功。正常提交回执内容校验继续保留。同版本恢复结果还须校验每条改动的当前内容；若已有后续版本，以不可改写的操作事件确认本次修改曾保存，不覆盖他人的后续修改。

恢复与独立回读各最多 3 次，只重试读取，间隔 0.5/1 秒；未登录/权限等 4xx 不重试。任何核对失败、账号切换、缺失或伪造操作均保留草稿。不盲目重复 POST。日志增加回执中断、读取失败重试、找回提交结果三个阶段；错误文字标明失败阶段，避免仅显示 Failed to fetch。

验证：跨设备专项新增提交前断网保留 31 项草稿、恢复上传、提交后丢回执自动恢复、短暂回读断网重试。独立 final-step 专项验证当前及后续版本、无写入、操作人不符、切账号、持续读取失败，断言最多一次 POST。原保存、日志、权限、分片和多人压力测试复测。所有测试均为隔离合成数据；没有用生产数据试写。

现场只读检查：数据库约 326MB，最新快照 V537 可完整校验；未登录 API 返回正常 401。不能凭此断言截图的 31 项已经保存，必须在原账号原电脑重试并核对日志。实时 tail 连接超时，未取得该次浏览器请求的服务端日志；故障的具体网络原因仍未确认。
