# 全部服务商遗漏区域专属物流商

日期：2026-11-13。候选修复，尚未部署；不修改报价数据。

## 已证实的问题

用户截图显示数据版本已更新，上方“全部服务商”仍只有仓库报价物流商。只读审计已核验目标服务商存在 27 条有效区域报价、0 条仓库报价。

`logisticsQuery` 原先只用仓库报价索引生成主服务商选项。`queryOptions` 同时会根据这份列表校验当前选择：区域专属服务商不仅不出现在选项中，即使客户端手动补上该项，服务端也会清掉 provider，并返回未按该服务商过滤的仓库报价。这不是用户没有发布或数据版本过旧。

## 修复与边界

- 查询仓库报价时，读取同一天、同版本、同评级规则的既有区域索引，补全服务商选项与名称。
- 在校验当前选择之前合并选项，保留区域专属服务商的选择。主表确实没有该服务商的仓库报价时返回 0 条，不回退为所有服务商。
- 下方区域请求继续沿用同一个 provider。页面在结果顶部明确显示仓库和区域条数，并提示区域专属服务商的报价在下方。
- 两种评级规则、运输方式、翻页、导出和两人独立操作保留。仓库表头列筛选仍只枚举该表实际仓库行，不把区域报价伪装成仓库报价。
- 部分旧测试/索引只有仓库分区时保持原行为；不要求新索引格式。原有目录别名不合并、不重命名。
- 不改原始日期、价格、清洗、覆盖规则、仓库模板、快照或冻结模块；不重建索引。新增运行时读取只访问既有不可变索引，不写 D1 记录。

## 版本与发布顺序

应用版本升为 V1.0.69，同步展示端、本地端、工具中心及资源缓存。原始 V1.0.68 到新版本的升级路径使用现有启动器测试。

先部署兼容旧页面的查询服务，核验线上只读查询的完整服务商列表与区域专属选择，再发布页面与桌面软件。无需发布、迁移或重建业务数据。此处涉及服务端查询规则，按 AGENTS.md 第 4 条在结果可审阅后取得明确上线授权。

回滚查询服务和本 PR 页面/版本元数据即可恢复旧行为；无需任何数据回滚。
