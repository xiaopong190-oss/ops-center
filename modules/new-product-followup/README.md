# 新产品工作台

同款产品一条父行，帐号与站点按子行管理。包括负责运营、当前动作、执行时间、头程物流、优化方案、任务验证、成本、推广、异常高亮和变更记录。

## 在另一台电脑使用

1. 解压整个压缩包，或从 GitHub 点击 Code → Download ZIP 后解压。
2. 双击 `index.html` 打开正式工作台。打开 `demo.html` 体验复杂示例。
3. 示例页刷新会重置；正式页尝试保存在当前浏览器的 IndexedDB。请检查界面保存位置提示，无法持久保存时会显示仅本次页面。
4. 搬运已有业务资料：在旧电脑正式工作台点击“导出备份”，将 JSON 文件单独安全传到新电脑，在空白正式工作台填写操作人后“导入备份”。非空工作区禁止覆盖导入。

**此代码包不包含浏览器中已录入的业务数据。GitHub 上传代码不会同步业务数据。** 不要将业务备份或帐号密码上传到公开仓库。帐号字段仅填写辨识名称，不填写登录凭据。

## 上传到 GitHub

新建仓库（团队内部资料建议 Private）。进入仓库 → Add file → Upload files，将解压后的本目录内容上传，保留 `work/`、`outputs/` 层级，提交即可。不要只上传 ZIP；ZIP 可另外放到 Release 供下载。

熟悉 Git 时也可在本目录执行 `git init`、`git add .`、`git commit -m "Initial new product workspace"`，然后按 GitHub 空仓库页面给出的命令关联仓库并推送。

## 网页访问（可选）

本目录的 `index.html` 可以作为静态网站首页。若仓库与帐号支持 GitHub Pages，在 Settings → Pages 中选择主分支、根目录。业务数据仍保存在每位使用者各自浏览器中，不会自动多人共享。发布前确认网站访问范围符合团队要求。

## 修改与测试

需要 Node.js 24 或兼容版本，日常打开网页不需要安装 Node.js。

```sh
npm run setup
npm run build
npm test
```

源码在 `work/`；基础模板在 `outputs/产品跟进网页/index.html`。构建后会生成完整网页、复杂示例，并更新根目录 `index.html`、`demo.html`。测试使用 jsdom 与模拟 IndexedDB，包含输入、导航、功能、边界、回归测试；当前 92 项通过。测试报告在 `outputs/`，实际浏览器视觉与存储权限仍需本机确认。

## 使用范围

这是可编辑的本地静态工作台，尚无服务器、登录权限、多人实时同步或防篡改认证。操作人手工填写；变更历史便于追溯，不等同于身份认证。默认示例证据链接是占位链接。
