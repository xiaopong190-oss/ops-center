# 清洗保存故障隔离方案

固定规则：仅Amazon范围、既有报价去重键、10天报价保存周期、永久仓库模板保持原样。新增解析仅补充原表有证据的渠道、路线、服务分段，不人为改价或改生效日期。

流程：原表解析与来源审计 → 原有规则清洗 → 现有AI异常复核 → 入库校验分流 → 保存完整性检查 → 本机保存 → 原有共享提交及确认。

本次实现针对整本Excel入库环节：区域逐条验证，按原有冲突键分组；同组多价格全部隔离，不选低价、不取平均、不任意保留第一条。其他区域及有效仓库报价继续保存。日期、价格、格式不合规的候选保存原始JSON、文件、工作表、行/单元格及原因，进入importExceptions，与有效报价分开，不进入比价。原有AI审查保持独立，不能自动将真实冲突价格判为有效。

分流要求区域输入数=通过数+待处理数；仓库坏行同样留痕。保存前继续原有assertImportCoverage检查。待处理记录随同一次本机数据写入保存，按完整原文及原因幂等去重，保存日起沿用10天窗口清理；模板不受影响。预览及区域留档区可导出待处理JSON。只有待处理证据时也允许保存，提示不能声称报价全部有效入库。

文件大小/结构错误、历史数据损坏、并发修改、容量不足及共享版本冲突仍停止相应写入，保留原有错误提示；网络失败不能显示共享提交成功。原表尚未解析出的内容继续依赖既有单元格审计与AI复核，本次隔离机制不等于所有未知版式都已识别。

回归要求：真实长河、GW、小满三份文件，原渠道服务分段、Amazon排除、历史去重和日期规则，混合正常与冲突、全部冲突、重复导入、证据导出、过期清理、无时效、保存覆盖检查。不得写入或调整真实业务报价日期做测试。
