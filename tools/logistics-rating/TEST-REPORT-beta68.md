# beta.68 导入异常高亮确认

在导入页新增常驻高亮异常提示。正常报价与异常证据分开保存；国家冲突、明确Amazon仓号的源金额格式错误、标准CSV坏行及已有区域价格冲突进入待处理列表。说明、占位符、暂停报价、已按范围排除的非Amazon不变成确认任务。AI已补回的同来源报价不重复提示。

上传人可“确认按原表导入”“更改后导入”“忽略，不导入”。同仓库、同来源国家冲突按组显示，WRO5的36条合成1条提示，可以整组确认或只修改本次国家/仓号；不会把不同价格批量改为同一金额。价格冲突明确选择一个价格时，按钮说明同条件其余价格将忽略并保留记录。无效金额、过期/未来日期及非Amazon编号仍不能强行确认。

确认/修改会重新执行既有报价校验、去重和保存覆盖检查，并记录人工确认、原始证据、操作者（页面可取得时）、时间和结果；未处理不入报价，忽略后保留证据，刷新和同原文重复导入保留已处理决定。操作沿用现有本机写锁、并发快照与GitHub提交，未有共享成功回执不能称共享入库。

已有仓库国家档案及历史报价不被自动改写。确认的新报价仍按既有规则提取仓库模板，因此可新增本次确认国家的仓库记录；历史冲突档案需在独立仓库纠错流程处理。Amazon范围、全局去重、10天报价/异常证据周期、仓库模板永久保留均保持原样。

真实长河隔离验证：使用现有共享仓库档案，正常2286条仓库与468条区域先保存，36条WRO5国家冲突单独保留。DOM页面出现1组高亮提示，显示原表波兰/档案德国。实际点击确认后为2322+468，待处理0，德国旧档案仍在，原始证据与36条人工决定完整保留。忽略、修改、无效价格拒绝、刷新状态及重复导入另有回归覆盖。

天盛1818+388、2206原始有效价格无漏；长河2322+468、GW2063+927、小满6915+270旧路径保持通过。所有操作在隔离数据进行，未替用户确认、修改或忽略真实异常；没有实测用户浏览器或实际AI提供方。旧版本未保留为待处理候选的36条，需要重新清洗一次才会生成新的高亮提示。
