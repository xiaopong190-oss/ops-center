# beta.73 关联502分阶段诊断及统计口径

截图HTTP502为服务端响应；请求通过页面到达API，但旧后端将未带status的返回解析/字段校验/数据库错误统一变为“服务请求失败”。目前共享关联缓存GET正常；未获取用户对应失败请求的具体异常日志，不能断言模型欠费、额度、数据库容量或模型返回格式就是本次唯一根因。

核对源码：运输数量为全局运输方式统计，未应用德国/BER8/服务商筛选；下方16062等为全局本周评级统计。当前列表54条与全局16062不是同一口径。修改标题明确“全局…未套用当前筛选”。未确认映射为尚未人工确认的比价口径，不是16062条价格丢失；单家参考价是缺少同条件有效同行。两者不是502的直接结果。

新增服务端分阶段错误代码：REL_CACHE_READ、REL_QUOTA_STORE、REL_PROVIDER_NETWORK（超时504）、REL_PROVIDER_HTTP_状态码、REL_OUTPUT_TRUNCATED、REL_RESULT_INVALID、REL_CACHE_WRITE。不返回密钥、请求头或模型完整正文；无效结果仍拒绝缓存与采用。原权限、额度、证据校验、干线不猜、价格与保留周期不变。

开启仅request_failed实时日志等待用户重试，本轮尚未捕获对应失败事件；部署后用户重试可得到具体错误代码，才能继续对症修复。新增后端单测覆盖超时、上游429、截断、格式/数量校验及写缓存失败。未实际调用用户AI额度或改变业务报价。

## 用户重试日志已确认的根因

用户回复“已点了”后日志捕获：/api/logistics-ai/recognize HTTP502，request_failed Error 关联结果字段无效。证实模型返回字段校验失败，不是上传失败或仓库数据丢失。原实现20项中一项不合法即整批抛错。

修复使用严格逐项字段校验：同标识合法结果正常保存缓存；字段不合规或缺项返回固定“待确认/低确定/可重试”，不写缓存、不采用猜测结果，不拖累本批其他正确结果。未知或重复输入标识仍整批拒绝。增加输出长度预留但仍有截断保护。前端明确显示无效项数量并可重试，仅重试未缓存项。测试包含实际复现类型“mode=快递派”不是合法干线、正确项仍缓存、无效项不缓存、伪造标识拒绝。
