# 邮编空运清洗补全

清洗目标是完整提取原表中有证据的报价，并保留每个候选价格格的结果；不能用上传成功代替清洗完整性。

原行为：空运服务分组表虽含邮编前缀和数值价格，单数字及逗号前缀可能无法通过预检；矩阵解析未继承国家列或明确目的国家标题，导致区域报价为零。

新行为：独立 `extensions/postal-air-layout.js` 仅处理可见空运表中原引擎已经识别的服务分组、邮编前缀和重量档布局。国家来自当前行国家列、工作表明确国家、或标题中明确的飞往/直飞等目的国家表达。冲突、缺失国家和非法邮编保留待核对。报价继续经过原 MatrixImport.build 与原运营排除投影，机场代码不转为仓库。每个非空候选价格格记录已提取、待核对或无有效报价状态；报告和逐格核查包保留原因。

影响：非锁定预检扩展、后台清洗 Worker、其入口脚本、三个页面加载清单和输入端运行资源清单。发布包及其启动后的本地 HTTP 服务验证新模块存在且可加载。锁定模块及其指纹不修改；不改已有报价、入库去重、十天有效期、仓库档案、计价/评分规则或线上快照。

验证：合成国家列/目的国家标题、单数字/逗号邮编、缺失/冲突国家、无效邮编、公式错误/单询/零价、起运地排除、重复投影及真实两阶段 Worker。用户原文件仅在本地验证：180 个空运价格格逐一原价匹配，60 个华南价格格保留，120 个华东/厦门价格格由现有规则排除；非空运可用结果与旧程序完全一致。原文件、提取数据和业务内容不进入仓库。

回滚：移除 postal-air-layout 扩展和预检/Worker/页面加载入口，恢复原清洗路径；无需迁移或回滚用户数据。

发布：本 PR 为本地实现与审查结果，未部署。依 tools/logistics-rating/AGENTS.md，清洗规则变更需审阅具体结果后的发布授权。上线后应重新清洗原文件并确认入库，再发布新快照；不得自动重发旧业务任务。
