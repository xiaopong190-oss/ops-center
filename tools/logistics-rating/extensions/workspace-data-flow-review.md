# 单人录入、多用户查询的数据流修复

用户确认：一名同事维护报价并发布，其他用户查询同一已发布快照。输入端本机主库与查询端缓存继续分开；多人共同编辑和自动合并不属于本次模式。

## 本次修复

1. 查询页增加区域/邮编报价查询。读取当前已加载数据库的全部区域记录，支持关键词、运输方式及分页，上方运输排除同步生效。原表中的邮编区域不伪造成 Amazon 仓库；原同仓评分规则保持原样。
2. 发布回执保存发布数据的内容摘要。本机后续同条数改价也能被识别为未发布变化；旧回执缺少摘要时明确显示未核验。
3. 发布预览与上传绑定登录会话，账号变化后禁止沿用任务或响应确认发布。浏览器 Web Locks 防止两个页面同时准备、发布或删除续传任务；无该能力的浏览器仍保留原单页忙碌保护与服务端版本冲突校验。
4. 查询状态直接显示已加载云端版本，便于和发布者核对。
5. Windows 更新及回滚的原子替换遇到 EPERM/EACCES/EBUSY 时最多重试五次，总等待上限 750ms；持续错误仍失败并保留恢复日志。

## 交付与回滚

独立分支和 PR，目标输入端版本 1.0.43。发布后原已入库的区域报价可直接查询；先前未入库的报价仍需重新清洗并确认入库后发布。查询用户使用刷新快照加载已发布版本。软件更新只替换应用资源，继续保留原浏览器、地址和业务库。

回滚代码可撤回新增查询模块及非锁定工作台接入点；无需迁移用户报价。新增回执摘要为可选字段，旧版会忽略。发布遵循 AGENTS.md 的具体结果审阅与授权要求。
