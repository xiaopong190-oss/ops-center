# 云端合作评价：保存边界与极限测试

状态：本地修复，生产仍为v1.0.19；未录入或修改生产评价。

## 测试发现

1. 旧代码允许第10,001条记录入库，随后读取会被10,000条保护拦住。现改为单条SQL中的容量条件，达到上限时不插入，原列表仍可读、自己的既有记录仍可编辑。9999条时100个不同运单并发新增，只允许一个占用最后名额。
2. 前一笔“已保存到云端”提示会在下一笔输入校验失败时残留。现于编辑及提交开始时清除旧成功状态，避免将上次回执误认成这次成功。
3. 客户端原来只检查ok及revision，没有核对回执中的实际运单/评分内容。现核对登录所有者、服务商/规范运单身份、渠道、日期、状态、评分与依据；错误回执不清空输入，不显示成功。

4. 保存往月走货后，页面仍停在本月，录入者看不到刚保存的记录。现保存成功后切至完成月份，同日期按更新时间优先显示。

另外，万条明细改为每页200条，月份汇总仍计算全部记录，待评价不计零分。分页不改变评分规则或云端保存内容。

## 边界与对抗

- 接受0、0.5、9.5、10分；拒绝负数、超过10、0.1步长、空值、布尔及非数字。
- 接受100字符运单和2000字符依据，拒绝越界。16,001字节请求无论预告Content-Length或流式实际到达都拒绝，数据库不写入。
- 三个月日期边界可保存，前一天、未来、反向日期和不存在日期拒绝。
- 100路同运单新增只成功一次；100路持相同旧revision的修改只成功一次，其他请求不能覆盖。
- 未登录、只读/老板角色、修改他人记录、伪造录入人、伪造服务商和原快照已登记运单拒绝。
- 模拟数据库已写入、读回回执丢失：界面保留草稿且不报成功；数据库仍只有一条，刷新能读到，重复新增拒绝。
- 快速连点只发一个请求，保存中冻结表单；失败后解冻并保留输入；错误回执、旧成功提示残留被专项测试拦住。
- 10,000条完整读取、上限拒绝、满额编辑和最后一个名额的并发测试通过。
- 10,000条月度评价合计准确，实际DOM只渲染200条，翻页不改计分覆盖。Node/JSDOM的渲染及翻页观测约0.3–0.4秒，不能据此承诺真实浏览器或弱网耗时。

## 验证方式与限制

独立SQLite、虚拟账号与运单、JSDOM真实表单及实际后端验证函数；网络与故障响应模拟。不证明生产平台在持续高并发下的资源上限，也未制造真实生产负载。

最终结果：22项合作评价专项、6项页面切换回归全部通过；37套完整全栈回归通过，跨月显示的最后修复另补跑了全部28项相关测试。未修改受保护的原评级、报价比较或清洗模块。
