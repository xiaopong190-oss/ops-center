# v1.0.15 — 本机容量检查与服务商数据管理（线下待发布）

## 行为

- 现有“本地数据与备份”页集中显示发布快照大小、32MiB 上限、完整本机大小及各类数据占用。上传前超限在本机拦截，并直达清理页，不发起无效的云端元数据请求。
- 主工具条只保留发布主操作；续传、备份与数据管理收进菜单。清理采用同一行的范围、服务商、数据类型和预览，不铺设一组常驻按钮。
- 可按具体服务商清理仓库/区域报价（含其删除留档）、异常原文、账单明细、合作记录，或合并选择这四类。服务商档案、公共仓库模板及其他服务商保留；不猜测未知归属，不按名称前缀模糊删除。
- 有同账号在本机成功发布的内容摘要时，可预览清理此后新增/变更的报价。缺少索引、换账号或索引不完整时不能宣称数据未发布；该模式不允许清理账单和评价。
- 删除预览显示分类条数、完整本机及发布快照清理前后大小。下载备份后，需要勾选确认已保存可用备份并输入“删除”。预览后数据变化时拒绝执行，要求重新核对。
- 清理会同时作废当前账号的本机旧上传任务，防止冻结快照重新传回已删记录。可单独清除旧任务，业务数据不变。上传仍进行时拒绝清理，需要先暂停并等待当前请求结束。
- 本次操作只写本机。重新确认发布后，云端展示将按本机结果更新；不会自动删除云端记录。服务端暂存分片继续按原期限回收。
- 写入失败不发送成功回执，并尝试恢复原值；持续存储故障需要保留备份并重新检查。本机多键存储不能宣称支持任意时刻断电后的全事务恢复。

## 边界与回滚

没有提高 GitHub 套餐额度，也没有放宽云端 32MiB 上限。此版本提供清理与任务解除阻塞；不承诺无限累计。原始导入、报价保留、比较、评分规则及12个受保护模块未修改。资料质量汇总在用户删除异常留档后通过既有模块重新计算，避免继续显示已删除原文的问题。

回滚移除 data-management.js、运行桥的管理命令、shell 管理面板和新增加载项；未执行清理时无数据迁移。已经人工确认清理的资料须用清理前备份恢复，软件降级不会自动恢复已删除业务记录。

## 验证范围

使用虚构报价，不读取或删除真实业务数据，不向生产快照写入测试内容。

- 32MiB 精确 UTF-8 边界（含中文）；50,000 条虚拟报价约46.05MiB，按服务商清理后约23.03MiB，其他服务商25,000条完整保留。
- 按类型和别名精确删除、冲突 ID 优先、空范围和伪造ID拒绝、损坏原文不扩大删除范围、缺失/损坏索引拒绝、已发布摘要匹配的报价保留、增量删除重建一致性。
- 真实运行模块的预览无写入、确认词错误、备份确认、并发修改、模拟存储写入失败恢复、只读及跨来源命令拒绝。
- 界面的折叠菜单、超限入口、服务商文本转义、备份回执前禁止清理；所有本地资源在便携服务白名单中。
- 保留既有上传续传、权限、云端存储、展示缓存、工作表识别、默认规则及其他全栈回归。

最终结果：408 项默认业务测试通过，34 套全栈回归全部通过。完整交付包90个资源校验和一致，隔离启动健康检查与新模块HTTP均为200，输入入口正常302跳转到200页面。浏览器实际核对了紧凑容量面板。未部署生产。
