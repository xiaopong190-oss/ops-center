# v1.0.16 — 统一单位、裸重量档和并排空派渠道（本地修复，未上线）

## 原因与修复

原表把人民币/kg写在重量表头上一行；重量档为10–20、21–70、501+等裸数字。多个下单渠道横向并排，渠道名纵向合并。原引擎既无法从裸档位识别完整计费表头，原报价预判也未关联分行的单位与目的地，因此生成0条报价。

新增纯扩展 `grouped-unit-layout.js`，仅在明确的RMB/KG单位、目的地区域列、“下单渠道 重量段”、合法裸重量档及空派渠道共同出现时启用。由原引擎处理每个渠道和计费档，保留原始价格、档位、单位、渠道和目的地坐标；不修改受保护的矩阵、入库或比较规则。

- 普货、带电、经济线、高货值及包税/不包税渠道分开。
- 仅继承真实合并区域内的渠道和时效，不向没有合并依据的空行填值。
- RMB明确为CNY，不随无关默认币种改变；保留原始档位标签和原始单位文字。
- 单询、暂停和说明不生成固定运价；附加费、查询页不当作基础运费。
- 缺失或冲突的国家仍由原校验拒绝；不凭仓库前缀猜国家。
- 同页独立的旧式报价区块保留，只替换本扩展处理的相同原价格坐标。
- 人工逐档核对页提示改用整本清洗；报价预判及实际后台Worker均加载同一扩展。

包含v1.0.15的容量检查和服务商清理。没有修改原始Excel，没有读取本机业务库，没有把测试结果写入云端。回滚移除本扩展、预判及Worker挂接和脚本引用即可；无存储迁移。报价日期、10天保留、AMZ范围、人工决定及国家冲突规则继续生效。

## 验证

真实附件通过原WorkbookPreview读取：13张工作表、163,943个有效单元格。完整后台清洗结果为1,940条仓库候选报价、460条区域候选报价。2,400条结果逐条核对原始价格坐标、金额、单位及渠道证据。未提供本机仓库档案的测试中，另有200条候选因国家无法唯一确定而保留为拒绝记录，不计为已通过报价。日本页单询没有编造为运价。此结果是本地测试，不是已经写入用户主库或云端的回执。

虚拟测试覆盖并排渠道、纵向合并、时效原坐标、税费和币种、区域邮编、坏价格、国家冲突、单询、非报价统计、独立旧区块共存、后台两阶段清洗和界面预览到确认入库。

最终结果：414项业务测试通过，34套全栈回归全部通过。完整端91个资源校验和一致，49个共享模块源指纹一致，新增识别模块及运行页HTTP均为200。生产尚未部署。
