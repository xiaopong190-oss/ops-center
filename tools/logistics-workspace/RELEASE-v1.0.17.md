# v1.0.17 — 报价判断、AI字段映射与入库衔接（本地版）

包含v1.0.15容量/服务商管理、v1.0.16共享单位和并排空派布局。新版不再把AI“看出有报价”视为已完成提取。

## 衔接修复

- `ai-quote-context.js`为纯证据投影：保留适用预判表头、统一计费单位、真实合并渠道，以及同价格列最近的重量档，避免只抽取附近几行而丢失远处表头。
- 有原文报价线索的未确认表可进入AI分类/字段映射，而不是在预判未覆盖时被永久排除。只有原价格、目的地归属、单位、币种、档位和国家/档案校验全部通过，才成为候选报价。
- AI不创建单价，不移动价格坐标；目的地必须属于本行或其真实合并区域；档位必须属于同价格列的适用表头。明确RMB保留为CNY，“不包税”优先判为不含税，不能被“包税”子串反向误读。
- 宽表按至多8个候选价格分段，保留源字段，遵守既有24行单元格/70上下文单元格的接口上限；未映射价格不算全部完成。超预算与超限原文保留，原有合法报价可继续。
- AI结果失败或未完全通过本地校验时不缓存，防止一次失败反复复用。缓存和在途请求按当前会话隔离。AI补清洗设置45秒批次预算，失败显示实际原因。
- 单项区域报价冲突先校验后合并，避免错误项部分插入。
- 补提取后更新每张表的条数、状态和预判来源；“已确认报价但提取为0”明确显示提取受阻和原因，不能显示已完成。核查包包含阶段诊断。

输入原Excel、已保存本机数据、默认日期/保留期、AMZ范围、国家档案冲突与人工决定均不修改。仍走原本入库校验。规则未支持或AI不能可靠映射的表会给出原因，不承诺任意表都能自动入库。

## 测试说明

虚拟未知布局经实际输入模块复现完整流程：AI先确认报价结构，规则提取为0，AI字段映射通过本地证据检查，逐表数量更新，再经正常确认流程入库。该AI链路采用模拟响应验证协议与状态，不是线上真实模型准确率评测。

测试覆盖远表头、合并归属、裸档位、币种税费、宽表分片、坏映射重试/缓存、会话隔离、部分映射、伪造仓号/价格/档位、只读权限、存储失败及全栈回归。九方真实附件的规则结果再次核验为1,940条仓库候选及460条区域候选，2,400条金额与原坐标一致；未带本机仓库档案时另有200条国家不唯一而未采用。

未修改云端AI协议和受控权限，也未向生产快照写入测试数据。回滚移除证据扩展、脚本加载及CleaningReview/界面衔接修改，无存储迁移。

最终结果：422项业务测试、34套全栈回归全部通过。完整包及补丁校验和与当前源码一致。只读健康检查发现原4318输入端仍为v1.0.12；没有自动关闭原服务或操作真实业务数据。本次交付v1.0.17供覆盖升级，生产未部署。
