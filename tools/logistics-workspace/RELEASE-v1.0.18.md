# v1.0.18 — 大快照分批加密存储与展示读取（待配套发布）

## 修改

发布快照保护容量从32MiB改为64MiB，上传仍走128KiB暂存分片、固定任务、摘要校验与原有断点续传。大于8MiB的发布数据不再保存为一个GitHub内容文件，而按512KiB原始字节切分，每批独立gzip、AES-GCM加密、按原文摘要寻址。每批写入后读回解密及摘要校验，只有全部通过才以GitHub SHA条件更新小型版本索引。旧版加密快照继续可读。原始数据和有效报价不删除。

失败重试可复用已经读回确认的GitHub数据批次；旧展示索引在新批次未完整确认时不变。GitHub密文文件仍位于既有data/logistics路径；既有Pages工作流忽略该路径，数据上传不会为每个批次触发前端构建。

展示端读取索引后按批取回，每次请求要求同一快照SHA，校验每批及整体摘要，全部完整后才写本机缓存。请求失败仅重试当前请求；切换版本、损坏或缺批次不会写入半成品数据。读回分页仍要求已有登录认证；本机中转只允许固定page和sha参数，不接受任意URL。

新输入端先检查云端声明的容量。若云端仍为旧版，明确提示必须配套更新云端，不建议删除有效数据。部署顺序：先部署支持分页的新展示端，再部署兼容旧数据的云端，最后使用新本地端发布；不要用只有本地文件的新版本替代云端部署。

## 限制

这不是无限容量方案；仍保护64MiB原始JSON及现有业务条数限制。暂存提交、增量重建和最终读回核验仍会在服务端组装完整数据，分批GitHub存储和展示下载不等于服务端全流式处理。生产Cloudflare CPU、内存、GitHub限流与真实弱网需上线后在原数据保留的前提下核验，线下模拟通过不能证明平台资源无限。旧版索引和已写密文批次暂保留，不自动删除历史文件。

本版本包含既有清洗修复、AI衔接、容量管理和启动竞态修复，不改业务主库和受保护清洗规则。回滚前先保留新索引；旧展示端不能读取新分页协议，不能仅回滚展示脚本而继续发布新分批快照。

## 验证

40MiB高熵虚拟数据81批：第3批网络中断，重试复用前2批，最终无重复写入并逐字节重建。35,000条有效虚拟报价大于32MiB：发布中断时旧索引未变化；全部批次验证后才发布，登录展示端逐批重建一致。另测错密钥、缺批次、损坏索引、SHA版本变化、未登录、客户端批次失败重试与保留旧缓存。64MiB上传边界及512个高熵分片验证通过。模拟GitHub与网络测试不向生产写入虚拟数据。

业务回归422项通过；超过32MiB的分批存储专项、客户端28项及64MiB传输边界测试通过。完整全栈结果见交付说明。完整端及覆盖补丁校验和与当前源码一致；尚未部署。
