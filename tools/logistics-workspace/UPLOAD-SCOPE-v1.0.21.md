# v1.0.21 发布范围与展示缓存核验

## 已确认的代码原因

`preview()` 优先恢复 IndexedDB 冻结上传任务；`publish()` 的断点续传和回执验证针对该固定任务。冻结后新增或修改的本机资料不会进入该任务。旧版成功提示只显示 SHA 和时间，无法说明“本批成功”与“当前本机全部已发布”的区别。

虚拟测试复现：固定批次 1 条，本机 2 条，旧批次仍可正确取得发布回执。本次修复保留断点续传，预览与回执同时返回固定批次、当前本机的仓库报价、区域报价、模板等数量，并按完整展示投影比较内容；相同数量的内容修改也会提示未发布变化。上传过程中新增内容也会在成功时重新核对。成功回执提示不会被随后的状态刷新隐藏。

展示缓存原先仅验证 JSON 和云端 SHA，不验证缓存业务内容。若缓存被业务模块写成另一个有效 JSON，相同 SHA 会继续复用。本次增加会话绑定缓存的 SHA-256 内容摘要；摘要缺失或不一致时重新下载。原版 10 天保留期等业务规则保持不变。

## 真实事件证据边界

先前截图：本机仓库报价 31113、区域报价 4091、模板 571；云端展示版本 402887770f 对应 18683、3399、414。差额 13122 条报价、157 个模板。本次没有访问同事电脑的冻结任务或解密云端原始快照，因此不能据此断言真实事件必然由旧任务导致，也不能声称缺少的数据已经补发。

安装补丁后，在原浏览器、原地址打开发布预览即可核对两个范围。若要发布当前已保存数据，选择“改发当前数据”，核对数量后发布；无需重新导入或清空本机数据。没有自动发布任何真实或虚拟报价。
