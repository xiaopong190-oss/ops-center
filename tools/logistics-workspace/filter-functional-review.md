# 联动筛选功能检查（1.0.47）

问题原因：仓库报价和区域报价分别渲染。最初区域模块未读取上方服务商等控件；1.0.46 补齐了一部分联动，但货物、税务和名称标准化仍未统一，运输方式自动填入局部筛选后也可能残留。原有独立模块测试未覆盖这些组合转换。

本轮使用合成报价加载完整发布版查询页面，在 operate / view 两种访问模式各运行 21 个场景，共 42 个用户操作场景。表格结果与独立预期数量核对，查询操作同时检查保存数据没有改变。测试代码位于 filter-functional.test.cjs；所有场景使用实际控件事件和原查询脚本。

| 检查范围 | 验证内容 |
|---|---|
| 服务商、国家、地区、渠道 | 单选、组合、标准化渠道、上下表同步 |
| 仓库编号 | 限定仓库表；区域表继续按邮编范围查询 |
| 运输方式 | 排除、范围外、全部；只剩一种方式后再切换范围 |
| 货物类型 | 单选、多选满足任一、全部货物按钮 |
| 税务方式 | 包税、不包税、未知及组合 |
| 区域局部控件 | 服务商、搜索、运输方式组合；不反向修改仓库表 |
| 分页与空结果 | 从第二页切换条件回第一页；无结果清空旧行 |
| 重置与比较评分 | 清除所有残留条件；比较后服务商筛选仍有效 |
| 数据保护 | 查询操作不改变报价存储；分页用例新增合成数据另行核验 |

本轮修复：区域报价使用与仓库表相同的名称投影和货物、税务筛选；显示原报价及来源；改变全局运输方式或运输范围时清除重复的区域局部运输方式条件。默认清洗、评分、保留期限和已发布业务快照不在此次修改范围。

验证边界：本报告覆盖完整脚本的 DOM 功能测试及回归，不代表读取了同事浏览器中的私有数据。线上上线后还要核验展示端脚本版本和交付文件一致性。

最终本地验证：679 项全量回归通过，其中完整页面联动矩阵覆盖 42 个用户场景（operate / view 各 21 项）。
